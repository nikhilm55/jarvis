**Why:** the owner has 3–4 Claude sessions left and needs a working product, not the full M2–M5 scope. Plan B keeps everything that makes Jarvis useful and safe on the owner's own Linux PC. It drops the setup wizard, the polish, the second OS and the rare features. It replaces the remaining tasks of `2026-10-16-m2-hands.md` and milestones M3–M5 of FRS §11 until the owner says otherwise.

**Done when** the owner can do this every day on their PC:

1. Log in. Jarvis starts on its own.
2. Say "Hey Jarvis, …" for any item in the checklist under [Acceptance](#acceptance-session-3), and it works.

## Sessions

Each session starts the same way:

1. Read this file and the ledger (`.superpowers/sdd/2026-10-16-m2-hands/progress.md`, local).
2. `git fetch`, then branch from `origin/main`.
3. Run `uv run ruff check . && uv run ruff format --check . && uv run mypy && uv run pytest -q -o addopts=""` on main.

Each session ends the same way:

1. Everything merged.
2. One ledger line per task.
3. Five minutes of live checks by the owner (listed per session below).

### Session 1: finish the hands

1. **Finish t9b** (≈ 30 min).
   - In `~/jarvis-t03b`: fix the lint in `tests/test_files_wiring.py`: the `match=r"^NOT_FOUND"` raw string, the long section line, and an unused `type: ignore`.
   - Run the full suite.
   - Commit, rebase onto main, then open and merge PRs for 9a and 9b.
2. **Shell tool** (plan t8, R84, R94–R99; the classifier is already merged). It must include G1.
   - **Runner:**
     - `ShellRunner.run(cmd, cwd, timeout_s)` runs `["bash", "-c", cmd]` in a new process group;
     - defaults: cwd = home, timeout 60 s, output capped at 64 KiB per stream;
     - the group is registered with the kill switch.
   - **Tool:** MCP `run_shell(cmd, cwd?)`. Its tier comes from `classify_shell`, and its consent scopes from the paths in the command.
   - **G1 fix:**
     - add the unknown wrappers to `_WRAPPER_SPECS`: strace, ltrace, perf, firejail, bwrap, `sg -c`, systemd-run, `script -c`, parallel, entr;
     - invert the data rule: a full-path dangerous basename is data only after a known non-executing head (cat, ls, grep, head, tail, wc, stat, file, cp, mv …);
     - corpus test: unknown wrapper × full path × {rm, sudo, `bash -c`} = T3.
   - **Owner's phrase 1:** the brain opens the terminal app (`open_app`), runs `git status` / `git log` as T0, and puts the answer in `display`.
   - **Owner's phrase 2:** "help me set up my project" runs a T2 sequence with one confirmation.
   - **Rules:** "use run_shell for commands; dedicated tools for files, windows, input".
3. **System controls** (plan t11, minus deep links and the unsaved-work heuristic).
   - **Controls:**
     - mute and output device (wpctl);
     - do not disturb (`gsettings … show-banners`), dark mode, night light;
     - brightness (`brightnessctl`, or `gdbus` to gsd-power);
     - media play/pause/next (playerctl);
     - Wi-Fi and Bluetooth on/off (nmcli, rfkill);
     - lock (T1); sleep, sign-out, restart and shutdown (T3);
     - `open_url` (T1, R83 provenance on the URL);
     - `system_info` (T0: battery, disk, memory, uptime).
   - **Missing tools:** a missing command is `UNSUPPORTED_ON_PLATFORM` with the install hint.
   - **Fast path, S6:** "set volume to 30 and turn on do not disturb" splits on "and" into two intents, both on the fast path.
   - **Lock and sign-out events** (FR-CON-09, R101): a logind D-Bus watcher (`gdbus monitor` on `org.freedesktop.login1`) ends session grants.
   - **FR-CON-16:** while the PC is locked, a consent answer by voice is refused.
4. **Live check (owner):**
   - "open the terminal and check what I've been working on";
   - "set volume to 30 and turn on do not disturb";
   - "Jarvis, stop" during a long answer;
   - "delete everything in Downloads" in YOLO on a test folder, then "undo";
   - "close Firefox".

### Session 2: eyes and integrations

5. **Screen** (plan t10, minus AT-SPI).
   - **Screenshot:** `screenshot(window?)` writes a PNG under `runtime_dir()` (scope `screen:read`). The MCP result carries it as **image content**, so the brain sees it. The file is deleted after the turn.
   - **Clipboard and selection:** `read_clipboard()` and `read_selection()` through xclip (scope `clipboard:read`). History is never read.
   - **S8 "summarise this":**
     - the selection when there is one, otherwise a screenshot of the active window;
     - the brain summarises into `display`, and speaks two sentences.
6. **Integrations through MCP** (M3, lite).
   - **Config:** `[integrations.<name>]` takes `command`, `args` and `env_keys`. Secrets come from the environment or a 0600 file, never from `config.toml`.
   - **Proxy, not pass-through:** jarvisd starts each server as an MCP client and exposes its tools to the brain as `<name>__<tool>`. Every call goes through `gated_dispatch`. Rule: one gate; Claude Code keeps `--strict-mcp-config` with only jarvisd.
   - **Inferred policy (FR-CON-01):**
     - scope `<category>.<name>:read|write`, with the category from the server name (mail, calendar, messages, files, browser) or set in config;
     - tier: tools named `get|list|search|read…` are T0 read, `send|create|update|delete|post…` are T2 write; anything unclear is T2;
     - a config override wins.
   - **Health:** `jarvis doctor` lists each server (started, tool count, last error); a server that will not start is skipped with a spoken remedy.
   - **Wired with the owner's accounts:** a browser (Playwright MCP) plus whatever the owner has: M365 (Teams/Outlook) and/or Google (Gmail/Calendar). Their tokens come from each server's own login, done once by the owner.
   - **Scenarios:** S2 "read my unread messages", S3 "message Rahul …", S5 "find the invoice PDF and email it", S7 "what's on my calendar today".
7. **`jarvis permissions`:** list grants (state, method, last used), `revoke <scope|source>`, `reset`. It shares the broker's admin methods with voice management.
8. **Live check (owner):** S8 on a selected paragraph; S7; S2; "allow Teams", then "what can you access".

### Session 3: product and acceptance

## How to work (to fit 3–4 sessions)

- **Who does the work:** Claude Opus implements and verifies directly. There are no subagents and no review rounds (owner, 2026-10-27). Checks:
  - ruff, mypy, the full suite;
  - a mutation check on safety rules only;
  - a live check where X or audio is involved, never typing into the owner's focused window.
- **PRs:**
  - one per task, size check ignored (the owner allows big PRs);
  - push with `scratch/merge/pr.sh BASE BRANCH`;
  - merge with `scratch/merge/ci_merge.sh PR…`, which waits until four test jobs pass.
- **Safety gate stays non-negotiable:** every new tool is a `ToolSpec` plus a `@tool_impl` through `gated_dispatch`, with scopes for personal data. The single-entry sensor test stays green. Its expected markers and operations get updated, never loosened.
- **Data and secrets:** never read the owner's data or secrets. Tests use `JARVIS_HOME=tmp_path`; manual runs use `JARVIS_HOME` set to a temp folder unless the owner runs them.
- **Ledger:** one line per task in the ledger. The rulings table in the M2 plan gets new rulings (next: R105).

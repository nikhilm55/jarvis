# M2 — Hands (Linux X11)

> **For agentic workers:** each task runs inside the agent harness (`harness/README.md`). The orchestrator turns a task below into a brief from `harness/brief.md`. The local model drafts through `scripts/local_model.py implement`, a Sonnet finisher completes it, and a task reviewer (Opus where marked) gates it. One PR per task (≤ 400 reviewable lines; split and stack if bigger). The owner merges.

**Goal:** Jarvis can act on the PC beyond opening apps: it can manage windows, type and click, read the screen, run shell commands, work with files and change system settings. Every action is governed by risk tiers, spoken or clicked confirmations, consent before touching personal data, and a kill switch that always works.

**Done when:** the M2 exit criteria pass in task 14's acceptance run on Linux X11:
- S1, S6 and S10 work;
- the prompt-injection test passes;
- no personal source is read without a grant outside YOLO;
- the owner's two phrases work: "open the terminal and check what I've been working on" and "help me set up my project".

Results are recorded in `docs/milestones/M2-acceptance.md`.

**Spec:** `docs/FRS.md`:
- §3.2 (S1, S6, S10)
- §5.8 FR-PC-01…24
- §5.10 FR-SAFE-01…10
- §5.11 FR-CON-01…19
- §6.5, §6.6
- §7.1, §7.8
- §8 and the frozen design `docs/design/jarvis-ui-mockup.html`: consent card, confirm card, Permissions screen, "controlling your PC" indicator.

**Stack:** ADR-0010 plus the ADRs this plan adds (task 10: ADR-0012).

**Out of scope:**
- the Windows backend and Wayland: their own milestones, per D15 and D17 (R80);
- integrations and MCP catalog (M3);
- main window, palette, setup wizard (M4);
- OCR and the vision fallback (R86);
- speaker verification (FR-SAFE-08, C); notifications (FR-PC-11, S), timers and reminders (FR-PC-12, S) and installing software (FR-PC-15, C), which move to M3; the setup consent step (FR-CON-18, M4 wizard).

## Global constraints

- Everything in `AGENTS.md`: Python ≥ 3.11, mypy `--strict`, ruff, `encoding="utf-8"` on all text I/O, no `shell=True`, tests with `tmp_path`/`monkeypatch`, never real user data (tests point `JARVIS_HOME` at `tmp_path`), ≤ 400 reviewable lines per PR.
- **One gate:** every tool call (fast path, brain via MCP, internal) goes through one `gated_dispatch`. No side doors (AGENTS rule 7, ADR-0004).
- **UI:** the UI matches the frozen design exactly (FRS §8.1). Cards use the `state-confirm` orb colour.
- **Latency (FRS §7.1):** first audible response ≤ 1.5 s p50; fast-path action after transcript ≤ 300 ms p50; barge-in "stop" → silence ≤ 300 ms p50 / 500 ms p95; idle CPU ≤ 3 % of one core.
- **Errors:** every tool returns structured errors with Appendix B codes (FR-PC-24), including `CONSENT_DENIED` and `UNSUPPORTED_ON_PLATFORM`.
- **Dependencies:**
  - Use what's present: python-xlib, stdlib, the system's `gio`, `gsettings`, `wpctl`, `nmcli`, `playerctl`, `fd`/`locate`/`find`.
  - A missing system tool returns `UNSUPPORTED_ON_PLATFORM` with a spoken remedy, never a crash.
  - A new Python dependency must be named in the task and added with `uv add`.
- **Harness standing rules** (`harness/brief.md`), especially:
  - atomic writes for the grants store;
  - one test per platform or allowlist branch;
  - postcondition checks before any success message.

## Interfaces (fixed here so parallel tasks fit together)

Changing a signature below needs the orchestrator.

|---|---|
| `policy` | `Tier` (T0…T3); `ToolSpec(name, tier, scopes, undoable=False, classify=None)`, where `classify(args) -> (Tier, tuple[str, ...])` refines the tier and scopes from arguments (shell, files). `decide(call: ToolCall, mode, ctx: TurnContext) -> Decision`. `Decision(action: Literal["run","confirm","consent","deny"], tier, scopes, prompt: str \| None, kind: Literal["voice","click","guardrail"] \| None, reason)`. `classify_shell(cmd) -> tuple[Tier, tuple[str, ...]]`. Deny/allow lists from `Settings.policy`. |
| `policy.gated` | `async gated_dispatch(call: ToolCall, ctx: TurnContext) -> ToolResult`: the **only** path from any caller to a tool. It decides, asks (via `Confirmer`/`ConsentBroker`), runs, audits, and records undo. `ToolCall(name, args, origin: Literal["fastpath","brain","internal"])`. |
| `confirm` | `Confirmer.ask(prompt, kind, target_phrase: str \| None, timeout_s=15) -> Answer(yes: bool, method: Literal["voice","typed","button","key","timeout"])`. Voice words are those of FR-SAFE-07, heard inside the follow-up window with no wake word. |
| `consent` | `Scope(source, access)`, parsed from `"messages.teams:read"`. `GrantStore(path)`: `.get(scope)`, `.grant(scope, lifetime, method)`, `.revoke(scope)`, `.all()`. | `killswitch` | `KillSwitch.trigger(source: Literal["voice","hotkey","hud"])`. It cancels the turn, kills registered process groups, drains queued calls and stops TTS within 300 ms. `register_process(pgid)`. |
| `desktop` (worker ops, added) | `list_windows`, `focus_window(ref)`, `window_op(ref, op)`, where `op` is one of minimize, maximize, restore, close, snap_left, snap_right, move_to_monitor, tile. | `a11y` | Helper process (`/usr/bin/python3`, gi + Atspi): `read_ui(window_ref) -> UiTree(nodes[ref, role, name, states])`, `find_element(label, role) -> ref`, `activate(ref)`. JSON lines like the desktop worker. |
| `shell` | `ShellRunner.run(cmd, cwd=None, timeout_s=60) -> ShellResult(exit_code, stdout, stderr, truncated, duration_ms)`. |
| `files` | `search_files(query, when, type) -> list[FileHit]`, `open_file`, `reveal`, `move`, `copy`, `rename`, `trash`, `delete_permanently`, `zip`; each declares its scopes from the path. |
| `hud` (events added) | `HudEvent` states gain `confirm` (with buttons), `consent` (card per §5.11.4), `controlling` (FR-SAFE-06 indicator with Stop), `access_badge` (FR-CON-14). Answers come back over the HUD loopback API (`POST /answer`, token + host guard). |

### Requirements and verify per task

Each item is testable. The task's brief numbers them, and the harness maps every one to a test.

**1. Policy v2.**
- (a) `decide` implements the §5.10 mode table exactly, with one parametrised test per (mode, tier) cell.
- (b) FR-SAFE-01 patterns: `rm -rf` outside temp, `del /s`, `format`, `diskpart`, `reg delete`, `sudo`, `curl … | sh`, `wget … | sh`, `Set-ExecutionPolicy`, `chmod -R 777 /`, `dd of=/dev/` all classify as T3, with a test each, including quoting and spacing variants.
- (c) The T0 allowlist: `ls`, `cat`, `head`, `tail`, `wc`, `pwd`, `git status`/`log`/`diff`/`branch`, `df`, `du`, `ps`, `uptime`, `which`, `echo` without redirection. Any `>`, `>>` or `| tee` lifts it to T2.
- (d) Deny/allow lists from `Settings.policy` (FR-SAFE-09) beat tiers. A deny-listed path is denied in every mode, YOLO included.
- (e) `gated_dispatch` is the only caller of tool implementations. A test asserts the fast path, the MCP server and internal callers all route through it, and an AST test finds no other call sites.
- (f) The audit record carries `turn_id`, tool, tier, mode, decision and who confirmed (FR-SAFE-10), and the activity log fills `policy_decisions`.

Verify: the policy test suite, plus a mutation check that removing the deny-list branch fails a test.

**2. Confirmations.**
- (a) Voice "yes / confirm / do it / go ahead / send it / no / cancel" inside the follow-up window, with no wake word, resolves the prompt. Anything else re-asks once, then counts as no.
- (b) HUD buttons, the `Y`/`N` keys and the typed box resolve it too (R82). The method is recorded.
- (c) A 15 s timeout = no, and it's spoken once.
- (d) T3 in Safe or Balanced needs a click. T3 in YOLO needs the spoken phrase repeating the target ("confirm delete").
- (e) Payments and credential changes can never skip confirmation.
- (f) R83 provenance: content-derived targets need confirmation in YOLO. The §6.6 phrasing is spoken.
- (g) The confirm card matches the mockup (screenshot test under Xvfb, as in M1 task 12).

Verify: tests with a fake `Speaker`/HUD; a screenshot diff against the mockup crop.

**3. Consent core.**
- (a) Every desktop, shell and file tool declares scopes (FR-CON-01). A test lists any tool without a declaration.
- (b) In Safe and Balanced, a call with an ungranted scope pauses, asks and resumes or cancels (FR-CON-02).
- (c) Lifetimes per FR-CON-09: session ends on brain reset, PC lock, sign-out or after 8 h. Each end gets a test.
- (d) YOLO auto-allows and logs it, but "never" and the deny list still block (FR-CON-10, OQ-006 as written).
- (e) Safe asks every turn and offers no "always" (FR-CON-11).
- (f) No answer in 15 s = no (FR-CON-07).
- (g) `CONSENT_DENIED` with the FR-CON-08 remedy.
- (h) The grants store follows R87; tests use adversarial files and a 0600 mode check.
- (i) Every prompt, answer and change is audited with its method (FR-CON-17).

**4. Consent UX.**
- (a) `jarvis.request_access(scopes, reason)` asks once per task for all scopes (FR-CON-03).
- (b) The wording follows FR-CON-04 and never bundles read and write silently.
- (c) Answers: voice, the card buttons, the `Y`/`S`/`A`/`N` keys and typing all work (FR-CON-05/06).
- (d) One prompt when both consent and confirmation are due (FR-CON-19).
- (e) Voice management (FR-CON-13): "what can you access", "allow Teams", "always allow my calendar", "revoke …", "forget all permissions". "Always" by voice also shows the card.
- (f) The access badge while touching a source (FR-CON-14).
- (g) The cloud-brain notice on the first send of personal data to Claude (FR-CON-15).
- (h) The card matches §5.11.4 and the mockup.
- (i) No consent can be granted by voice while the PC is locked (FR-CON-16).

**5. Kill switch.**
- (a) "Jarvis, stop" while speaking silences within 300 ms p50 / 500 ms p95 when echo cancel is present (R88). It's measured with a played fixture.
- (b) `Ctrl+Alt+Esc` cancels the turn, kills registered process groups and drains queued calls (FR-SAFE-04).
- (c) HUD Stop does the same.
- (d) "Jarvis is controlling your PC" with Stop shows whenever input tools run (FR-SAFE-06).
- (e) The brain is re-warmed in the background after a cancel (backlog).
- (f) Jarvis's own long answer never starts a turn (self-trigger test with echo cancel on and off).

**6. Window tools.**
- (a) Each FR-PC-02 op works on a real X11 window under Xvfb in CI-skipped live tests, and on a fake backend in unit tests.
- (b) S1: "open Teams" (or Calculator in CI) leaves the app focused and in front, checked with `_NET_ACTIVE_WINDOW`.
- (c) A missing window gives `NOT_FOUND` with alternatives.
- (d) FR-PC-01 completed: `list_apps` and `is_running`, an app index that includes Flatpak and Snap `.desktop` exports, and aliases from `Settings`.

**7. Input tools.**
- (a) `type_text` is Unicode-safe and uses the clipboard above 200 characters, restoring the clipboard afterwards.
- (b) `press_keys` parses combos like `ctrl+shift+m`.
- (c) `click(x,y)` and `scroll` go through XTest.
- (d) The indicator shows during input (5d).
- (e) Typing dictated text into the focused field needs no consent (§5.11.1 "not personal") but is still tier-gated.

**8. Shell tool.**
- (a) R84 classification, with the table from 1(b, c).
- (b) Process group, timeout, 64 KiB cap, separate streams.
- (c) Killed by the kill switch within 300 ms.
- (d) Path arguments add file scopes (`cat ~/Documents/x` asks for `files.documents:read` in Balanced).
- (e) The owner's phrase "open the terminal and check what I've been working on" works: the terminal opens and `git log`/`git status` in the project dir runs as T0. The answer is in `display` and the spoken text is short.
- (f) "help me set up my project" runs a T2 sequence with one confirmation.
- (g) The brain reaches the shell only through this MCP tool. It keeps `--tools ""`, so Claude Code's own Bash stays off (FR-PC-09's "same hook" is satisfied by having no other path).

**9. File tools.**
- (a) `search_files` uses `fd`, then `locate`, then `find`, with `when`/`type` filters.
- (b) `trash` uses `gio trash` (T2), and `delete_permanently` is T3.
- (c) §6.5 end to end: YOLO "delete everything in Downloads" → "Moved N files … Say 'undo'"; "undo" restores them; "permanently" → the guardrail.
- (d) Undo for move/rename (R90).
- (e) Every op declares scopes from its path.

**10. Screen understanding.**
- (a) ADR-0012 records the AT-SPI helper.
- (b) `read_ui` returns a simplified tree with refs for a GTK test app.
- (c) `find_element(label, role)` and `click(element_ref)` activate a button in the test app.
- (d) `screenshot` writes a PNG under `runtime_dir()` and needs `screen:read`.
- (e) Clipboard and selection need `clipboard:read`, and history is never read (FR-PC-05).

**11. System controls.**
- (a) Each FR-PC-06 control has a backend: mute and output device (wpctl), DND (gsettings `show-banners`), dark mode, night light, brightness, media keys (playerctl/MPRIS), and Wi-Fi/Bluetooth (nmcli/rfkill).
- (b) Lock is T1; sleep, sign-out, restart and shutdown are T3, with an unsaved-work check by window title heuristics (FR-PC-07).
- (c) `open_url` and system info (FR-PC-13).
- (d) Settings deep links (`gnome-control-center <panel>`).
- (e) S6: "set volume to 30 and turn on do not disturb" runs both on the fast path within the §7.1 fast-path budget.
- (f) Lock screen: only T0 non-personal actions run while locked (FR-PC-23).

**12. Permissions page.**
- (a) Lists every scope with its state, when and how it was granted, and when it was last used.
- (b) Revoke, "Reset all to Ask" and "Revoke everything" work (FR-CON-12).
- (c) Opened by voice and by `jarvis permissions`.
- (d) Matches the mockup's Permissions screen.

**13. Voice-loop fixes.**
- (a) An empty transcript after a wake drops silently (B2).
- (b) A polite decline shows as a normal reply, not an error (B3).
- (c) Idle CPU ≤ 3 % with a real mic: measure the share of VAD-speech frames in a quiet room and tune (B4).
- (d) `scripts/bench_stt.py` compares `tiny.en` and `base.en` on accuracy and latency; switch the default only if `base.en` keeps p50 ≤ 800 ms (B5).
- (e) First audio ≤ 400 ms p50 if reachable; the reply is not queued behind the thinking earcon.

**14. Acceptance.**
- (a) Scripted runs on real components for S1, S6, S10, §6.5, §6.6 (a text file with injected instructions; the brain is asked to read it), the owner's two phrases, and every consent case in §7.8.
- (b) 0 guardrail bypasses; 0 personal-data touches without a grant outside YOLO; every failure with a spoken remedy.
- (c) The owner's live run checklist, recorded with numbers in `docs/milestones/M2-acceptance.md`.
